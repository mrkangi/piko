# PikPak 下载服务设计

状态：M0–M5 已在本地实现并通过假 HTTP／假后端自动化测试（真实 PikPak 账号端到端验证仍需测试账号授权执行）。部署拓扑、组件依赖与链路详见 [ARCHITECTURE.md](ARCHITECTURE.md)。

## 1. 产品范围

这是部署在 NAS 或服务器上的独立 Go 服务。浏览器负责配置来源、查看进度和控制任务，文件由服务端写入服务器的下载目录，不经过浏览器。服务位于 Piko 仓库内，未来使用自己的 `go.mod`、构建和容器镜像，不进入 Gradle，也不依赖 Piko 客户端、会话或 MQTT。

首版面向单账号、单管理员、单实例。支持配置一个下载根目录和多个 PikPak 监控目录，周期递归扫描，也可立即扫描；自动下载新文件、保留目录层级，任务可暂停、继续、取消和重试。只下载原始字节，不处理转码。默认使用单流下载；用户可显式把单文件分片连接数调到 2 以上，使达到阈值的大文件按连续 Range 分段并发下载。单文件并行度与最小分片大小在 Web 管理页配置；改回 1、不满足阈值或下载节点不支持 Range 时使用单流。**对 PikPak 只读；远端移出、改名或消失，都不自动删除、搬动或覆盖已交付的本地文件。** 不做双向同步、分享转存、自动切换后端或多实例调度。

## 2. 组件与上游边界

| 组件 | 职责 |
| --- | --- |
| `cmd/server` | 装配配置、单实例锁、HTTP 服务和后台工作组；处理优雅退出。 |
| `internal/pikpak` | 账号会话、分页列目录、按 ID 查详情、拉取原始流；将上游错误转换为服务可识别的类别。 |
| `internal/catalog` | 管理监控来源，递归扫描，计算差异并生成下载意图。 |
| `internal/download` | 领取任务、控制并发、管理暂存及退避、验证并交付文件、启动恢复。 |
| `internal/store` | SQLite WAL、迁移、状态条件更新、扫描发布与任务去重。 |
| `internal/web` + `web/` | 前后端分离：React + TypeScript + Vite + Tailwind CSS v4 独立前端（`web/`），后端提供认证、CSRF、REST 与 SSE（`internal/web`），生产可独立托管或 `-tags embed_ui` 单二进制嵌入。 |
| `internal/notify` | 订阅任务/扫描事件，向飞书群机器人或通用 Webhook 发送通知；渠道 URL 与密钥加密存储。 |

以 [`52funny/pikpakcli`](https://github.com/52funny/pikpakcli) 的 `560f263661fc55e40e508fe8e0d4b151c855dcbd` 为初始参考。真正引入代码时保留上游 MIT 许可及版权声明，记录引入的文件和改动。只取 `internal/api` 中需要的登录、刷新、列表、详情和原始流逻辑；不引入 Cobra、交互 Shell、mpb、全局配置或 `http.DefaultClient` 修改。服务不启动 `pikpakcli` 子进程。

在消费侧保留两个小接口，不做插件系统：

- `Catalog`：`ListPage(ctx, parentID, cursor)` 返回条目和下一页游标；`Stat(ctx, objectID)` 返回当前元数据。条目至少有 ID、父 ID、名称、类型、大小、修改时间和可选内容指纹。
- `ContentSource`：`OpenOriginal(ctx, expectedObject, offset)` 按预期文件版本打开原始字节流；返回已验证的起点和总长，或返回明确的版本不符、不可续传等错误。适配器负责协议判断；服务负责写盘、进度和控制。

不把上游 DTO、临时 URL 或 `*http.Response` 暴露给调度器及浏览器。将来替换适配器时须确认对象 ID、版本语义和账号映射相同，否则重建目录基线，旧的 `.part` 不跨适配器续传。

## 3. 来源、目录与扫描

每个来源固定绑定一个远端目录 ID 和一个唯一的本地别名。Web 可浏览远端目录来选择来源；远端路径只用于展示。映射为 `<下载根>/<来源别名>/<远端相对路径>`，例如 `/TV/Shows/Season 1/a.mkv` 在 `Shows` 来源下写入 `/downloads/Shows/Season 1/a.mkv`。来源可重叠，但各自有独立索引和输出目录；不跨来源去重。

- 首次添加来源，显式选择「下载现有文件」或「只监控新增」。后者把**首次完整成功扫描**中的文件版本记为基线，不将它们入队；此后新对象或明确的新内容版本才入队。失败的首扫不建立基线。每个来源可配置最小文件大小，小于阈值的文件仍写入远端索引，但不生成下载任务；阈值为 `0` 时不限制。
- 每个来源同一时间只跑一轮扫描。默认间隔 5 分钟，支持单来源「立即扫描」和「扫描全部已启用」；手动扫描与定时扫描合并，失败退避，扫描期间来源状态显示为 `RUNNING`。扫描失败采用连续失败防抖：阈值内显示 `RETRYING` 并继续退避重试，达到全局阈值（默认 3 次）后才进入 `FAILED` 并发送一次 `scan.failed` 通知；任意一次成功扫描清零。按目录分页流式写候选代，不把整棵树常驻内存。只有根目录仍可访问、所有分页与子目录成功且结果通过校验，才事务提交候选代、差异和下载任务。失败、取消、游标循环、重复对象 ID 或响应结构异常时，不发布差异；保留上一份成功结果。
- **不能原样复用上游的列表行为。** 上游遇到验证码响应可能更新令牌后继续解析原响应，其他 API 错误也可能被读成空目录。适配器必须检查 HTTP 状态和 API 错误码，有限次重试同一页；只有符合列表响应契约的成功结果才允许返回空页。
- 远端目录不是原子快照。首版要求连续两次完整成功扫描缺失才标为「不在监控范围」；失败的扫描不增加缺失计数，重新见到即清零。根目录不可访问是来源异常，不是整棵树被删。仅证据明确时才展示「已删除」，首版不主动区分移出目录、回收站和删除。缺失标记只写数据库，不创建旁路标记文件。已确认缺失的对象停止自动派发；在途任务不因扫描结果推测而强制删除暂存。
- 交付记录保存独立的本地实际路径。远端重命名或移动后，更新远端路径，已交付文件保持原位并标出路径差异；在途任务使用领取时固定的目标路径，不在下载中途改写。新文件按扫描到的路径落盘；目标路径已有本地文件时直接采用该文件、不下载也不覆盖，任务标记完成并记录「本地已存在」。首版仅下载文件，不同步空目录。
- 服务端下载根目录可由启动配置初始化，也支持管理员在 Web 管理页修改与浏览服务器目录（切换前须无活动下载任务，并通过磁盘原子交付探测；只影响后续新任务，禁止后台搬动已有文件）。Web 可批量勾选或单个添加要下载的 PikPak 目录，并可调整扫描间隔、启停或移除监控（移除不删本地文件）。

## 4. 持久化与状态

SQLite 使用事务管理下列状态，凭据不进入业务表。进度按节流策略落盘，不逐块写数据库。

| 表 | 保存内容与约束 |
| --- | --- |
| `sources` | 来源 ID、账号标识、根目录 ID、唯一别名、首次扫描策略、启停、扫描周期、最小文件大小、最后成功代。停用停止扫描和新派发，不删除文件或索引。 |
| `scan_runs` / `scan_entries` | 扫描状态和候选目录记录，按来源及扫描代隔离。提交后清理候选；启动时回收未完成的候选。 |
| `remote_objects` | 来源内对象 ID、当前远端路径、版本、最后出现代、缺失计数。按 `(source_id, remote_id)` 唯一。 |
| `download_tasks` | 绑定不可变对象版本；记录任务状态、用户意图、执行次数、下次尝试时间、错误分类、暂存和目标位置。按 `(source_id, remote_id, version_key)` 去重；重试沿用任务。 |
| `download_task_segments` | 多连接下载的分片范围与各段已确认偏移。只保存连续 Range 计划；服务端忽略 Range 时写入单段回退标记，后续恢复继续走单流。 |
| `deliveries` | 已交付的对象版本、实际本地路径、大小及校验信息；同一目标路径只允许一份交付记录。 |
| `notification_channels` | 飞书/通用 Webhook 渠道、加密 URL 与密钥、事件过滤、启停状态。 |

PikPak 网络代理使用 `app_settings.proxy_url_cipher` 保存 AES-GCM 密文，不保存明文地址。代理支持 `http://`、`https://`、`socks5://`（以及等价的 `socks5h://`），可包含用户名和密码；SOCKS5 由代理端解析目标域名。空值表示直连，不读取进程环境中的 `HTTP_PROXY`/`HTTPS_PROXY`。

内容版本优先使用 `GCID + 字节长度`；GCID 缺失时，可使用能证明字节身份的上游版本标识。没有可靠标识时，大小和修改时间只能作为**发现变更和入队的线索**，不能证明暂存或已有文件等同于远端。对象版本变化时，旧任务不能继续下载新版本；新版建立独立任务，已有最终文件仍不覆盖。

任务状态：`QUEUED → RUNNING → VERIFYING → COMMITTING → COMPLETED`。其他状态为 `PAUSING`、`PAUSED`、`CANCELING`、`CANCELED`、`RETRY_WAIT`、`FAILED`、`CONFLICT`。远端可见性与本地交付状态单独记录，不用远端消失来改写已完成的下载历史。

| 操作 | 规则 |
| --- | --- |
| 暂停 | 排队任务直接暂停；运行任务先持久化暂停意图，再取消 worker 的 `context`。等响应体和文件都关闭才进入 `PAUSED`，保留暂存并释放槽位。暂停不消耗重试额度。 |
| 继续 | 仅从 `PAUSED` 重新入队，领取时跳过 `attempt` 自增，领取前重新检查对象版本和暂存。单流从连续偏移续传；分片任务按每段已确认偏移分别续传，不预分配 `.part`。 |
| 取消 | 与暂停共享停止流程，但终态为 `CANCELED`；默认在 worker 退出后清理该任务的暂存，不触碰最终文件。扫描不会重新派发同一取消版本，用户可显式重试。 |
| 提交 | `COMMITTING` 是控制边界：提交前受暂停/取消约束；一旦原子领取提交权，控制请求返回冲突并让 UI 刷新结果，不承诺撤回。 |

调度器使用 SQLite 条件更新领取任务和变更意图，同一任务只允许一个活动执行者；外发控制操作可重复调用。默认两路文件下载，控制面 API 请求单独限流；磁盘不足时不新派发。网络断开、`429` 和可重试 `5xx` 用有限次数带抖动退避，尊重 `Retry-After`；过期直链重新查详情，不盲重放同一 URL。分片传输遇到 `429/503` 时停止派发新的 Range，已建立的连接完成当前分片后退出，按轮次减半并发并带抖动退避；单连接仍遇 `503` 时刷新直链有限重试，之后才进入任务级重试。每个下载节点最多同时保留 5 条连接，分片连接启动时错峰；管理页把单文件分片连接数改为 `1` 时立即取消并发的 Range 轮次，保留从 0 开始的连续已完成前缀后切换到无 Range 单流。认证失效或配额耗尽暂停相应派发并给出原因，路径冲突不能靠重试解决。

## 5. 续传、落盘与恢复

1. **重新确认身份。** 开始或恢复前按文件 ID 查详情并比对预期版本。`.part` 及其身份记录由服务托管；只在 ID、可验证版本和总长均匹配时按实际落盘长度续传。分片任务还会核对连续段计划与每段偏移；身份不匹配时清空暂存并重建计划。版本已变，不在旧任务下写入新内容；仍缺乏可靠版本证据时，即使元数据看起来相同也从零开始。
2. **拒绝错误字节。** 单流续传和每个分片都必须收到可验证的 `206`，校验 `Content-Range` 的起点、结束位置、总长与实际响应字节数，禁用透明解压。若分片请求收到 `200`，不拼接任何分片，由服务清零暂存并回退单流；单流续传遇到 `200` 也从零重试。`416` 本身不代表完成；仅在版本与本地完整长度已确认、并通过提交校验时走交付。对不完整响应仅保留已经确认属于正确连续范围的字节。
3. **隔离暂存。** 使用同一文件系统中的 `<下载根>/.staging/<task-id>/payload.part`，对普通下载目录不可见。保存前逐段映射远端名称，识别保留名、大小写及 Unicode 归一化碰撞。拒绝路径穿越和符号链接逃逸，使用受根目录约束的文件操作，不只靠字符串前缀判断；远端名称不能占用 `.staging`。开始下载前与发布前都检查目标：本地已有普通文件时直接采用，任务标记完成并记录「本地已存在」。
4. **校验再交付。** 核对字节长度，若有可计算的可信远端哈希则比对；无可靠哈希时明确是长度校验。记录服务计算的本地摘要供交付恢复核对，不把它冒充为远端内容校验。先持久化提交意图及本地摘要并同步暂存数据，再检查目标名仍不存在，最后用同卷改名发布（Android 共享存储与 exFAT 同样适用）。若目标在下载期间出现，则放弃暂存、采用本地文件并标记完成。目录 fsync 不支持时降级。
5. **按证据恢复。** 单实例锁确保旧进程不会与新进程同时写盘。有暂停或取消意图的任务按意图收尾，不擅自重跑。其他中断任务检查 `.part` 后重新入队；`COMMITTING` 如目标已存在且是普通文件，直接采用本地文件并标记完成；否则按持久化提交意图和本地摘要复核，确认才补记交付。数据库里的进度只是快照，恢复以磁盘为准。

进度每秒采样，速度取近几秒滑动窗口，ETA 仅在总长、有效速度均已知时展示。区分「已有字节」和「本轮收到的字节」，恢复时不会因已有暂存产生虚假高速度。阶段性进度节流写库，状态切换立即落盘。

## 6. Web 与部署

- **信息架构与布局**：一级导航为概览、下载任务、文件索引、管理设置，运行日志从顶栏入口进入。桌面使用固定侧边栏、紧凑表格与高密度工具栏；移动端使用底部导航、卡片列表和设置子页，可点击区域不小于 44px，筛选与分页不产生页面级横向滚动。概览汇总实时速度、空间与来源异常、活动任务、最近完成、存储余量和来源健康度，并可跳转到对应筛选。
- **页面**：管理页分为下载与存储、监控来源、账号与代理、通知渠道、系统与升级五个分区，桌面用分区侧栏、移动端先显示分区列表再进入子页；脏表单在底部吸附保存/重置。任务页显示状态、进度、速度、ETA、失败原因、「本地已存在」标记与可用操作；文件页显示远端相对路径、本地实际路径、缺失及冲突；任务与文件索引按服务端 50 条分页，搜索和总数统计在 SQL 层完成，SSE 只按事件范围刷新相关数据；运行日志页读取有界内存环形缓冲，页面侧限制渲染条数，支持按级别筛选与导出；全局眼睛按钮默认脱敏，可切换任务与文件路径显示。
- **接口**：`GET /api/setup/status`、`POST /api/setup` 负责首次配置；`GET /api/remote/folders` 分页浏览远端目录；`GET/POST /api/sources`、`PATCH/DELETE /api/sources/{id}`、`POST /api/sources/scan`、`POST /api/sources/{id}/scan`；`GET /api/tasks`、`POST /api/tasks/{id}/{pause,resume,cancel,retry}`；`GET /api/files`、`GET /api/system/settings`、`PUT /api/system/settings`、`GET/PUT /api/system/account`、`PUT /api/system/proxy`、`PUT /api/system/admin-password`、`GET/POST /api/notifications`、`PATCH/DELETE /api/notifications/{id}`、`POST /api/notifications/{id}/test`、`GET /api/events`、`GET /healthz`。列表分页。操作异步执行时返回已受理和当前状态，非法状态转换返回 `409`。浏览器以 SSE 事件触发合并刷新，首次连接和断线重连均重新取快照；SSE 不是持久状态来源。
- **会话**：每账号一个长期客户端，按请求传递 `context`；以绝对过期时间管理令牌，串行刷新并原子落盘，避免并发请求重复轮换。鉴权及验证码失败可见，不循环刷登录。服务使用独立凭据和会话文件，不读取任何桌面版或 CLI 的配置。
- **安全**：管理员密码使用 bcrypt 哈希；PikPak 密码和网络代理 URL 使用数据目录内 `secret.key` 的 AES-GCM 加密后存入数据库，代理只向管理页返回脱敏地址。默认监听 `0.0.0.0:7788`，首次配置必须提交控制台打印的 Setup Token；公网部署应放在 TLS 反代后。管理 API 与 SSE 都须鉴权，写操作校验 CSRF；配置与令牌不回显，日志不记录真实文件名、账号、令牌、验证码、代理凭据和带签名直链。
- **部署**：只读取 `DOWNLOAD_SERVER_HOST`、`DOWNLOAD_SERVER_PORT`、`DOWNLOAD_SERVER_DATA_DIR` 三个环境变量。数据目录默认 `$HOME/.pikpak/downloader`，保存 SQLite、`secret.key`、会话和服务锁；下载目录默认 `$HOME/PikoDownloads`，可在 Web 管理页修改。容器用非 root 用户运行，不挂 Docker socket；不让实例共享同一个 SQLite 数据目录。NAS 可将下载目录作为本机挂载卷，但必须通过交付语义检查。

## 7. 完整阶段计划

首版按 **M0 工程底座 → M1 PikPak 适配 → M2 来源扫描 → M3 下载执行 → M4 Web 管理 → M5 部署发布** 推进。阶段结束以可运行产物和验收结果为准，不以代码目录是否建好为准。M2 和 M3 可用同一个假后端开发；M4 的完整体验必须等两者都接通。当前已完成首版实现，真实 PikPak 账号和实际 NAS 挂载卷仍需按验收清单做上线前冒烟。

| 阶段 | 依赖 | 交付物 | 完成标准 |
| --- | --- | --- | --- |
| M0：工程底座 | 无 | 独立 `go.mod`、服务入口、配置校验、数据目录与单实例锁、SQLite 初始迁移、假后端测试设施、独立 CI | Go 服务可独立构建；初始化和重启不丢数据；同一数据目录拒绝第二个实例；不改 Gradle、不要求真实账号即可跑测试。 |
| M1：PikPak 适配 | M0 | 记录上游来源与许可；账号会话、分页列表、元数据、原始流和错误分类；开发用只读验证入口 | 第二页遇到认证错误时重试原页，其他错误绝不当空页；并发请求只刷新一次；覆盖合法 `206`、错误范围、忽略 Range 的 `200`、`416` 及短响应。经授权的真实账号验证列目录、原始字节和断点读取，并记录无法续传的场景。 |
| M2：来源扫描 | M0；真实接入依赖 M1 | 来源管理、唯一别名、定时与手动扫描、候选代发布、文件索引及去重入队 | 两个来源独立保留递归目录；两种首次扫描策略可重复验证；同一对象版本不会重复入队；分页失败、根目录不可用不改已发布索引；连续两轮成功扫描缺失才标记，重新出现解除标记。 |
| M3：下载执行 | M1、M2；可先用假后端 | 任务调度、并发与退避、进度采样、暂停／继续／取消／重试、受限暂存、校验交付及启动恢复 | 暂停并重启后可从正确偏移继续，输出与参考字节一致；版本变化后不会拼接旧数据；取消后不被扫描重排；覆盖磁盘满、本地已存在采用、符号链接、暂停与提交竞态，以及交付后数据库未记账的恢复。 |
| M4：Web 管理 | M2、M3 | 来源页、任务页、文件页、REST、SSE、管理员认证和 CSRF 防护 | 管理员能选远端目录、立即扫描、看进度／速度／ETA 并控制单任务；能筛选远端缺失、失败和冲突；SSE 断线重连后状态一致；未认证或跨站请求不能读状态或修改任务。 |
| M5：部署发布 | M4 | 独立容器镜像、配置示例、部署与备份恢复文档、发布冒烟检查 | 非 root 容器可部署在目标 NAS／服务器；挂载卷支持不覆盖交付，重启后任务与文件一致；完成两来源端到端演练以及备份恢复演练；保留已交付文件时可停用服务，不执行自动清理。 |

**阶段门槛**

- **M1 → 真实接入**：真实只读验证未获账号授权时，可继续用假后端开发，但不能宣称 PikPak 实机验收通过。首次验证只使用测试账号和约定的测试文件，不对远端写入。
- **M3 → Web 集成**：以两条端到端用例把关：某一页扫描失败不产生缺失标记；单个文件下载中暂停、重启、续传后产物正确。Web 不负责补偿底层任务状态错误。
- **M5 → 首版可用**：在空数据卷上部署，配置两个来源，分别验证存量和仅新增模式；新增嵌套文件能自动落盘；远端移出后只显示标记，本地完整文件仍在；暂停、取消、重启和重新扫描后状态一致。测试账号预置数据或远端移动由授权测试人员完成，服务仍只读。

### 首版之后

以下是独立迭代，不计入 M5，也不预设上线顺序：

| 后续迭代 | 启动条件 | 验收重点 |
| --- | --- | --- |
| 更灵活的本地文件管理 | 用户确实需要随远端改名或迁移下载目录 | 先给变更预览；仅处理服务已确认交付的文件；不覆盖用户文件，可从中断恢复。 |
| 更细的分片调度 | 连续大段分片仍受单连接抖动影响 | 引入 aria2 式小块位图和空闲连接抢块，按吞吐动态调整连接数；须继续保证版本固定、分段校验与恢复一致。 |
| 更多后端或账号 | 有另一个明确的使用场景 | 用同一套列表、版本、取消和恢复契约测试验收；凭据、索引和暂存按账号隔离；不假设跨后端 `.part` 可复用。 |

## 8. 首版交付清单

- 服务器可独立部署，下载根和持久卷可由部署者配置。
- 一个 PikPak 账号可同时监控多个目录，首次策略、定时扫描和手动扫描均可用。
- 新文件按来源别名及相对目录递归落盘；远端消失默认只标记，本地不删除、不移动、不覆盖。
- 任务可在浏览器查看进度、速度、ETA 和失败原因，可暂停、继续、取消、重试；重启后保持可解释的状态。
- 具备适配器自动化测试、故障恢复测试和实际部署冒烟步骤，并有可执行的备份恢复说明。
