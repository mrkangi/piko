# PikPak 下载服务架构

状态：已按首版架构落地。产品规则与 M0–M5 验收见 [DESIGN.md](DESIGN.md)。

## 1. 系统部署

```text
浏览器 ── HTTPS ── TLS 反代 ── HTTP ── 单个 Go 进程
                                          ├── $HOME/.pikpak/downloader：SQLite WAL、secret.key、实例锁、账号会话
                                          ├── /downloads：已交付文件、私有 .staging
                                          └── 出站 HTTPS：PikPak API、原始文件下载节点
```

浏览器是控制面，只收目录、任务、进度和状态，不代理下载字节，不接触 PikPak 凭据或直链。首版目标为 Linux 容器或 Linux 主机、单账号、单实例；没有 Redis、外部队列、独立 worker 容器或 CLI 子进程。启动只接受 HOST、PORT、DATA_DIR；首次配置通过带 Setup Token 的 `/setup` 完成。下载卷必须支持服务所选的不覆盖交付语义；不能通过启动探测的挂载不派发任务。

## 2. 组件与依赖

```text
cmd/server：组装依赖、管理生命周期

web ──来源命令──▶ catalog  ──Catalog───────▶ pikpak ──▶ PikPak
 │                   └──────扫描事务──────▶ store  ──▶ SQLite
 ├──任务命令──▶ download ──ContentSource──▶ pikpak
 │                   ├──────任务事务──────▶ store
 │                   └──────写入与交付────▶ localfs ─▶ 下载卷
 └──列表查询──────────────────────────────▶ store

catalog / download ──状态变更通知──▶ web / SSE ──▶ 浏览器
```

图中扫描、任务和查询均通过存储接口访问 SQLite；Web 不直接执行 SQL、发起下载或操作文件系统。接口由使用方定义，适配器不反向调用业务层。

| 包 | 管什么 | 不管什么 |
| --- | --- | --- |
| `cmd/server` | 启动配置、挂载探测、实例锁、依赖注入、启动和退出顺序 | 扫描及下载规则 |
| `internal/catalog` | 监控来源、扫描触发、候选代、差异、下载意图 | 数据流和本地文件写入 |
| `internal/download` | 任务操作、领取和重试、传输控制、进度采样、交付恢复 | PikPak 请求格式、SQL 和 HTTP handler |
| `internal/pikpak` | 从 `pikpakcli` 适配只读 API、串行刷新、预期版本检查、Range 响应验证 | 调度、写文件、Web |
| `internal/store` | SQLite 迁移、候选发布事务、条件状态更新、查询投影 | 发网络请求、持有下载流 |
| `internal/localfs` | 路径映射与占用、任务暂存、空间检查、不覆盖交付 | 远端目录与任务调度 |
| `internal/web` | 管理员认证、来源/任务/文件页面、通知渠道管理、REST、SSE | 令牌存储、直接改任务表 |
| `internal/notify` | 飞书与通用 Webhook 通知、事件过滤、发送重试 | 下载调度、扫描决策 |

## 3. 数据所有权

| 信息 | 权威来源 | 恢复规则 |
| --- | --- | --- |
| 来源配置（含每个来源的最小文件大小）、扫描结果、任务意图与交付记录 | SQLite | 队列直接从任务表重建，不从 SSE 或内存恢复。 |
| 暂存和最终字节 | 下载卷 | 单流恢复取连续落盘长度；分片恢复以 `download_task_segments` 的每段确认偏移为准，并核对磁盘范围、身份和提交证据。 |
| 实时速度、ETA、活动 worker | 内存 | 重启后归零，在下一轮采样时重建。 |
| 管理员与 PikPak 凭据 | `admin_users` 与 `app_settings` | 管理员密码使用 bcrypt；PikPak 密码使用 `secret.key` 的 AES-GCM 密文；任何管理 API 都不回显密码。 |
| PikPak 会话 | 数据目录内账号会话文件 | 刷新成功后原子写回；服务内串行刷新。 |

远端对象以 `(来源 ID, 远端对象 ID)` 标识，下载任务额外绑定内容版本。源目录路径、当前远端相对路径和已交付的本地路径是三项不同的数据，不能互相覆盖。不同来源别名不共享目标命名空间；进入下载前还需检查文件与目录互斥、大小写及归一化冲突。

## 4. 四条主链路

**来源同步**

1. Web 浏览远端目录或提交选中的目录 ID。来源服务校验目录及唯一别名，保存首次扫描策略。定时器和手动入口使用同一套去重机制。
2. 扫描器读取根目录下的所有分页和子目录，每页写入独立候选代，网络请求不占用数据库事务。
3. 完整成功后，在同一事务中发布索引、比较对象版本并创建下载任务；失败或中止的候选代不参与差异计算。
4. 连续两轮成功缺失才标记「不在监控范围」，停止自动派发该对象，已交付本地文件保持原状。重新出现时解除标记，不重排用户取消的同版本任务。

**文件下载与交付**

1. 调度器只领取符合条件的任务，在同一事务中固定尝试编号和目标路径。首版默认两个活动下载，API 扫描与详情请求遵守独立的限流预算。
2. 适配器按文件 ID 重新确认版本，再打开原始流；流只到 worker。大文件按连续 Range 拆成最多 N 段，由 N 个连接并发写入任务自己的 `.part`；每段只向前推进，段偏移节流落库。节点忽略 Range 时清空分片状态并回退单流。worker 以各段确认字节之和计算进度与速度。
3. 大小和可用哈希校验通过后，条件提交 `COMMITTING`，保存提交意图和本地摘要。发布前再次检查目标；目标已是普通文件时直接采用本地文件，任务标记完成并记录「本地已存在」，不下载也不覆盖。
4. 目标不存在时，将已同步的完整暂存文件用同卷改名发布到最终路径，再同步目标目录。交付只依赖改名与文件 fsync，Android 共享存储（FUSE）和 exFAT/FAT32 SD 卡同样可用。同步目标目录后在 SQLite 事务中记交付并完成任务；目录 fsync 不可用时降级，崩溃恢复用提交摘要核对目标。

**任务控制**

1. REST 写入用户意图并条件更新状态。活动任务收到暂停或取消时，取消本次尝试的 `context`；只有尝试退出、流和文件都关闭后才进入终态。排队任务无需启动 worker。
2. 继续重新排队，不复用旧流；暂存与预期版本匹配才追加。取消仅清理此任务的私有暂存，不操作最终文件。`COMMITTING` 获得提交权后不再接受撤回，API 返回冲突并要求刷新状态。
3. 尝试编号约束进度、错误和完成更新，旧回调不能改写新尝试。状态提交后发通知，Web 以分页快照为准，SSE 仅通知刷新，断线重连后重新取快照。

**进程重启**

1. 获取实例锁，验证配置和卷，打开数据库并迁移；回收未发布的扫描候选，保留最后一次成功索引。
2. 先处理暂停、取消意图，再核对 `COMMITTING`：目标已存在且是普通文件则采用本地文件并标记完成；目标不存在且暂存已验证则重试发布；目标是已发布的同一文件且摘要匹配则补记交付；其余异常停在冲突或失败，不覆盖。
3. 将无用户停止意图的中断下载重新排队；单流按文件连续长度恢复，分片按每段已确认偏移恢复，并核对确认过的版本。完成恢复后再打开写接口和后台派发。正常退出先停止接受写操作和领取任务，再关闭后台工作组；已记录的状态用于下次启动恢复。

## 5. 安全与运行边界

- 服务只实现 PikPak 只读操作；没有远端写入口。Web 认证与 PikPak 登录完全独立，同源部署、管理接口和 SSE 鉴权、写请求校验 CSRF。
- 下载根由部署者配置，浏览器只提交来源别名和远端 ID；所有暂存和交付操作限制在服务持有的根内，拒绝符号链接路径和跨卷交付。下载目录不作为 Web 静态目录开放。
- 管理员可在 Web 管理页修改服务端下载根并浏览服务器目录；切换前会校验无活动任务并重新执行卷探测，所有暂存和交付操作始终限制在当前持有根内，拒绝符号链接路径和跨卷交付。下载目录不作为 Web 静态目录开放。
- 下载和扫描出错分别处理：扫描失败保留旧索引；传输暂时故障有界重试；认证、配额、磁盘不足阻止相关新派发，给出分类状态。日志和健康端点不披露账号、真实文件名或签名 URL。
- 健康检查区分进程存活和服务就绪：迁移、挂载验证、恢复未完成时不就绪；PikPak 临时不可达不触发进程重启，管理端仍可查看原因。

## 6. 阶段对应

| 里程碑 | 拉通的架构边界 |
| --- | --- |
| M0 工程底座 | 进程、配置、实例锁、数据库、假后端。 |
| M1 PikPak 适配 | `Catalog` 和 `ContentSource`、账号会话、真实原始流验证。 |
| M2 来源扫描 | 来源管理、候选发布、目录索引和持久队列入队。 |
| M3 下载执行 | 队列领取、任务控制、落盘、交付和失败恢复。 |
| M4 Web 管理 | 管理员面板、REST 和 SSE，与扫描及任务状态接通。 |
| M5 部署发布 | 镜像、挂载与运行边界、端到端冒烟和备份恢复。 |
